# 스크린샷에서 조립한 새 원본 - 파이프라인 (재설계) 쪽에 넘기는 설명서

2026-10-19. 더미앱 하나의 이체 캡처 19장 (`inputs/captures/transfer/*.png`, 파일 이름 순) 에서 사람 정보 없이 조립한 원본
HTML 입니다. 만든 줄은 `tools/screen_detect/assemble/` (README 의 "조립 1 · 2단계" 절), 이 폴더는 `--inputs strict` (감사 훅) 로
만들었습니다. 검사기 이야기는 `origin/feat/db-principles` 의 `senior_ui/audit` 코드를 읽고 쓴 것이고, 이 원본으로 검사기를
실제로 돌려 보지는 않았습니다.

## 1. 넘기는 파일 (`llm/`)

| 파일 | 무엇 |
|---|---|
| `llm/original.html` | 새 원본. 화면 13개 = `section.screen[data-screen="s01"…"s13"]`, 창 390x844, `show()` · `window.__screen()`, `#phone` 위임 처리기 하나 (`if(a==='…') show('sNN')`). 생김새는 LLM (프롬프트 v3), 동작 이름은 규칙. 모든 요소에 `data-src` (검출 요소 id) |
| `llm/flow.json` | 흐름 파일 (아래 2). s01 → s12 과제 길, 오류 경로 1개 |
| `llm/trace.json` | 요소마다 어디서 왔나 - 화면 · 선택자 · data-action · data-v · 검출 상자와 글 · 의미 층 칸 · 마크업 출처 · 쓰인 이동. 키는 `"sNN:요소id"` |
| `llm/limits.md` | 이 실행의 한계 - 이은 짝 · 비운 칸 · 닿지 않는 화면 · LLM 호출 기록 · 무리가 갈린 화면 |

같은 동작에 규칙 마크업을 입힌 판은 `rule/` 에 있습니다 (견주기용). 둘 다 출력 검사 ①~⑤ 0건, 걷기 시험 이동 12개 모두 됨.

## 2. flow.json 이 flows/ 형식과 다른 점

- 더한 칸 (검사기는 읽지 않음): `screens` (화면마다 캡처 · 요소 수 · 무리 이름), `transitions` (모든 이동 - 누를 것 · 짝 ·
  `via`), `blank` (비운 칸과 까닭), `note`. steps 의 걸음에도 `via` 가 있습니다.
- `via`: `tap` (흐름 짝 그대로), `skipped-states` (사이 상태 캡처가 없어 처음 누른 것으로 바로 다음 캡처 화면 - s01→s02,
  s06→s07), `keypad-advance` (숫자판의 숫자 키 하나로 다음 화면 - s10→s11, s11→s12. 이동에 `v_match: "^\d$"`),
  `error-recover` (오류 화면에서 되돌아감).
- 비운 칸: `truth` = `{}` · `required_ids` = `[]` · `expect` = `{}` · `done_amount` 없음 (정답 값과 DOM id 가 스크린샷에
  없다). `error_paths[0]` 의 `about · condition · uses · notice_any · inputs` 가 빈 값 (오류 조건과 입력이 스크린샷에 없다).
- `derived_from_original: true`, `task: null`, 화면 이름은 `sNN` (뜻 이름 없음), data-action 은 `a-sNN-kk` · 무리는
  `a-sNN-gK` + `data-v` (값이 첫 data-*).

## 3. 검사기별로 되는 것 / 안 되는 것

| 검사 | 이 원본으로 | 까닭 |
|---|---|---|
| A 과제 완수 | 도달은 됨 · 금액 왕복은 안 됨 | steps 로 s01~s12 에 닿고 `.screen.on` 과 `__screen()` 이 맞음. 금액 값 (truth.AMOUNT) 과 완료 화면 금액 자리 (done_amount) 가 없음. derived 이므로 재설계가 data-screen 13개 · data-action 이름 112개를 모두 지녀야 함 |
| C 죽은 조작부 | 됨 | 처리기가 `a==='…'` 꼴이라 handlers.BRANCH 가 읽음. 과제 밖 누를 것 (분기 없는 data-action) 은 원본에서 이미 죽어 있던 것이라 새 결함으로 세지 않음 |
| F 언어 | 됨 | 원본 글이 기준 |
| I 선택지 | 됨 | 무리 = 같은 data-action 형제. LLM 판은 숫자판 · 목록이 줄마다 다른 부모로 갈렸으나 (s04 · s06 · s07 · s08 · s10 · s11), probes._CHOICES 가 부모마다 형제 2개 이상인 묶음을 합쳐 세므로 값은 같음 (형제 하나뿐인 줄은 없음). steps 로 닿는 상태만 봄 |
| J 오류 경로 | 안 됨 | `inputs` 가 비어 오류를 다시 낼 수 없음. 오류 캡처 (11.png) 가 완료 캡처 (10.png) 다음에 찍혀 `from_step` · `back_to` 가 완료 화면 s12 - J 는 back_to 가 완료 화면이면 안 된다고 봄. 과제의 오류 id (틀린 계좌 · 틀린 은행) 와 이름 (`e1`) 도 다름 |
| K 과제 밖 입구 | 판정 안 됨 | 새 원본에 `oos-*` 이름이 없음 - 원본을 걸을 때 과제 파일의 entrances 를 하나도 찾지 못해 지킬 입구가 0개가 됨 (코드로 본 것). 과제 밖으로 보이는 누를 것 (목록 대조 기준 95개) 은 지켜지지 않음 |
| L 그림 자리 | 됨 | `.pic[role=img][aria-label]` 130개, 이름은 의미 층 (스크린샷에서) |
| M 흐름 고정 | 맞춰야 됨 | M 은 과제 파일의 원본 흐름 (`tasks/<과제>.json` 의 flow) steps 와 견줌 - 이 flow.json 의 sNN 이 아님 |

## 4. 한계

- 찍지 않은 상태: s01→s02 (홈 → 받는 사람) · s06→s07 (증권사 → 금액) 사이 상태 (은행 고르기 등) 는 캡처가 없어 만들지
  않았고, 처음 누른 것으로 바로 다음 캡처 화면으로 갑니다 (via skipped-states).
- 숫자판: 비밀번호 화면은 숫자 키 하나만 눌러도 넘어갑니다 (몇 번 눌러야 하는지 모름, via keypad-advance).
- 오류 조건 · 입력 · 알림 단어: 없음 (스크린샷에 보이지 않음). 오류 화면은 하나 (s13) 뿐입니다.
- 정답 값: 은행 · 계좌 · 금액 · 이름이 없습니다 (캡처에 보이는 글은 마크업에 있으나 "정답" 으로 정하지 않음).
- 검출 놓침: 만드는 줄은 알 수 없습니다. 옛 원본과 견준 목록 대조 (`llm/lists.md`) 에서 옛에만 있는 것 - 선택지 값 4 ·
  그림 자리 9 · 과제 밖 입구 6 · 입력칸 3, 캡처 없는 옛 상태 (오류 wrong-bank 등).
- 넘침: 줄 · 카드가 누를 것이 되어 과제 밖 누를 것이 옛 원본보다 70개 많습니다 (연구자 결정 - 놓침보다 넘침).
- 이 숫자는 더미앱 하나의 이체 캡처 19장에서 나온 것입니다.

## 5. 이 원본으로 재설계를 돌릴 때 연구자가 정해야 할 것

1. truth: `"truth": {}` 이면 파이프라인의 load_flow 가 과제의 필수 키 (은행 · 계좌 등) 가 없다고 멈춥니다. 칸을 지워 과제의 truth 를 쓰게 할지 (사람 정보가 파이프라인 쪽에서 들어감), 캡처에 보이는 값으로 채울지.
2. M 흐름 고정: 견줄 원본 흐름을 이 flow.json (s01~s12, 11걸음) 으로 바꿀지, 과제 파일의 원본 흐름 이름 (home · recipient …) 에 sNN 을 맞춰 줄지.
3. J 오류 경로: 오류 입력 · 조건 · 알림 단어를 사람이 적어 넣을지, 이 원본에서는 J 를 빼고 돌릴지. 오류 캡처가 완료 뒤라 back_to 가 완료 화면인 것도 함께.
4. K 과제 밖 입구: 과제 파일의 entrances (oos-*) 를 이 원본의 `a-sNN-kk` 이름에 사람이 짝지어 줄지, K 를 판정 없이 둘지.
5. A 금액 왕복: done_amount 와 금액을 정할지 (정하지 않으면 도달만 판정).
6. via 로 이은 이동 (skipped-states 2 · keypad-advance 2) 을 과제 길로 받아들일지.
