앱으로 한 과제를 하며 차례대로 찍은 캡처들이다. 캡처 짝마다, 앞 캡처에서 무엇을 눌러 뒤 캡처가 되었는지 추정하라.

받는 것
- 캡처 목록 (찍은 순서 = 파일 이름 순, JSON 한 줄에 하나): file · unit(요소 목록의 단위 - 한 화면을 스크롤하며 찍은 캡처들은 한 단위다).
- 단위마다 누를 수 있는 요소 목록 (JSON 한 줄에 하나): id · text(화면 글, 글 없는 그림은 그림 이름) · kind(역할) · group(무리).
- 답할 캡처 짝 목록.
- 그림: 짝마다 앞 캡처와 뒤 캡처를 줄인 그림 두 장 (그림 이름표에 짝 번호와 file 이 있다). 글 목록과 그림이 다르면 그림을 따른다.

지키는 규칙
1. 캡처 짝 목록의 짝마다 답을 하나씩, 빠짐없이 낸다.
2. tap 은 앞 캡처(from)의 단위의 요소 목록에 있는 id 이거나 null 이다. 목록에 없는 요소를 만들지 않는다.
3. tap_text 는 그 요소의 text 를 그대로 쓴다. 화면 글을 바꾸지 않는다. tap 이 null 이면 tap_text 도 null 이다.
4. 캡처에 없는 화면을 지어내지 않는다. 두 캡처 사이에 캡처되지 않은 상태가 있었다고 보이면 kind 를 skipped 로 적고, tap 에는 앞 캡처에서 처음 누른 것으로 보이는 요소를 적는다 (모르면 null).
5. 같은 화면을 스크롤했을 뿐이면 kind 는 scroll, tap 은 null 이다.
6. 뒤 캡처가 잘못된 입력 때문에 생긴 오류 상태이면 kind 는 error_path 다. 앞 캡처에 그 오류를 낸 요소가 없으면 tap 은 null 이다.
7. 모르면 kind 를 unknown 으로 적는다. confidence 는 그 답이 맞을 확률(0~1)이다.
8. JSON 하나만 답한다. 그 앞뒤에 다른 글을 붙이지 않는다.

답의 모양
{"pairs": [{"from": "<file>", "to": "<file>", "tap": "<id>" 또는 null, "tap_text": "<글>" 또는 null, "kind": "<kind>", "confidence": 0~1, "reason": "<짧은 근거>"}]}

- kind 는 다음 가운데 하나다.
  - tap: 앞 캡처에서 하나를 눌러 바로 뒤 캡처가 되었다
  - scroll: 같은 화면을 스크롤했다
  - skipped: 사이에 캡처되지 않은 상태가 있다
  - error_path: 뒤 캡처는 잘못된 입력이 낸 오류 상태다
  - unknown: 모른다
