# 디자이너용 변경 설명서

최종: 생성 (시도 1)

실행 `20261012-132226` · 시도 1 에서 검사를 통과한 빌드 · 커밋 `82b866c46ca4`.

이 파일은 구조 시안의 설명이다. 색·글꼴·간격 같은 시각 디테일은 평가하지 않았다. 화면 구성과 흐름, 그리고 바꾼 이유를 옮겨 적는다.

## 화면 대응

| 원본 | 재설계 |
|---|---|
| home | home, services |
| recipient | recipient, services |
| bank | bank |
| account | account |
| amount | amount, services |
| confirm | review, services |
| password | verify |
| done | done, services |
| err-account | account |
| err-bank | bank, review |

재설계 화면의 순서와 하는 일:

1. `home` — 출금할 계좌를 확인하고 이체를 시작한다. 다른 금융 기능도 여기서 찾아간다.
2. `recipient` — 새 계좌로 보내기 또는 기존 계좌 목록에서 선택하기를 정한다.
3. `account` — 받는 계좌번호를 입력하고 은행을 선택한 뒤 계좌번호를 검사한다.
4. `bank` — 은행이나 증권사를 이름으로 찾아 선택한다. 선택 후 계좌 입력 화면으로 돌아간다.
5. `amount` — 보낼 금액을 입력하고 출금가능금액과 비교한다.
6. `review` — 받는 계좌, 보내는 계좌, 금액과 수수료를 확인하고 필요한 항목을 수정한다.
7. `verify` — 출금계좌 비밀번호를 입력하고 명시적인 최종 실행 버튼으로 이체를 진행한다.
8. `done` — 완료된 이체의 금액과 받는 계좌를 확인하고 홈으로 돌아가거나 후속 기능을 이용한다.
9. `services` — 원본의 부가 메뉴를 이름으로 찾아 이용한다. 이체 중 열었다면 입력을 보존하고 이전 단계로 돌아간다.

- **D5** `account` 계좌번호 입력 안내와 다음 버튼 — ‘없이 숫자만 입력’에서 무엇을 빼라는 것인지 알기 어렵다. 다음 버튼이 흐리지만 계좌번호와 은행 중 무엇이 부족한지는 설명하지 않아 진행 방법을 찾기 어렵다. (근거[화면+코드]: 그림 5 계좌번호 칸에는 ‘없이 숫자만 입력’이 보이고, 은행 선택 칸과 하단 다음 버튼은 연한 글씨로 보인다. 코드의 account-next는 계좌번호가 비었거나 은행이 없으면 아무 안내 없이 반환하며, renderAccount는 두 값이 있을 때만 버튼의 외관을 바꾼다.)
- **D6** `account` 숫자 키패드와 삭제 조작 — 처음에는 숫자 키패드가 없어 입력을 시작하려면 어디를 눌러야 하는지 알아내야 한다. 키패드가 열린 뒤에는 숫자 사이의 버튼 경계가 없고 삭제가 기호뿐이라 잘못 누르거나 수정 방법을 못 찾을 수 있다. (근거[화면+코드]: 그림 5에는 키패드가 없고 그림 6에는 계좌번호 칸을 누른 뒤 화면 아래 숫자들이 나타난다. 숫자는 흰 배경에 따로 놓여 있으며 마지막 칸의 삭제는 기호만 보인다. 코드에서 acc-field를 눌러야 S.accPad가 켜지고, 입력 후 나타나는 ⓧ는 계좌번호 전체를 지운다.)
- **D7** `bank` 기관 목록과 은행·증권사 전환 — 작은 기관 이름을 세 열에서 비교하며 여러 번 내려야 해서 비슷한 이름을 잘못 고를 수 있다. 흐린 증권사 탭을 선택할 수 없는 글자로 오해할 수도 있다. (근거[화면+코드]: 그림 7~9에는 큰 네모 그림 아래 작은 기관 이름이 세 열로 배치되어 있고 목록이 세 장에 걸쳐 이어진다. 상단 증권사 글씨는 은행보다 흐리다. 코드에서는 두 목록을 따로 그려 놓고 tab-sec를 눌렀을 때 증권사 목록을 보여 준다.)
- **D8** `amount` 금액 질문, 받는 계좌 및 출금계좌 변경 — 핵심 질문과 출금가능금액이 흐려 읽기 어렵다. 보내는 계좌와 받는 계좌가 위쪽에 작은 글씨로 모여 있고 받는 계좌를 ‘아래 계좌’라고 불러, 어느 계좌로 보내는지 다시 확인하기 어렵다. (근거[화면]: 그림 10 중앙 ‘얼마를 보낼까요?’와 바로 아래 출금가능금액은 연한 글씨다. 상단에는 긴 출금 통장 이름, ‘아래 계좌로’, 작은 은행명과 계좌번호가 이어지며, 출금계좌 변경은 통장 이름 끝의 작은 아래 화살표로 표시된다.)
- **D9** `amount` 빠른 금액 버튼과 잔액 초과 입력 — 빠른 금액 버튼을 다시 누르면 금액이 누적되므로 원하는 금액보다 크게 입력할 수 있다. 잔액을 넘기는 숫자를 눌렀는데 화면이 그대로이거나 빠른 금액이 잔액으로 바뀌면 터치 실패로 오해하거나 의도하지 않은 금액을 확인할 수 있다. (근거[화면+코드]: 그림 10 빠른 금액 버튼은 짧은 약식 표기이며 전액 버튼도 같은 줄에 있다. 코드의 quick는 기존 금액에 금액을 더하고 잔액을 넘으면 Math.min으로 잔액에 맞춘다. num은 잔액 초과 숫자 입력을 설명 없이 무시한다.)
- **D10** `confirm` 이체 요약과 메모 — 실제 받는 사람 이름을 확인했다고 착각할 수 있다. 계좌정보는 작은 요약 행에 있고 김철수라는 이름은 메모에만 표시되어, 메모를 계좌 명의자로 잘못 읽을 가능성이 있다. (근거[화면+코드]: 그림 11 큰 질문은 ‘아래 계좌로’라고 되어 있고, 김철수는 ‘받는분 메모’와 ‘내통장 메모’ 행에만 나타난다. 코드에서는 두 메모가 고정된 글자이며 계좌 명의자를 조회하거나 표시하는 처리는 없다.)
- **D11** `confirm` 정보 수정과 보내기 버튼 — 은행이나 금액이 틀린 것을 발견해도 해당 항목을 바로 고칠 버튼이 없다. 보내기를 누르면 곧바로 송금되는 것으로 생각할 수 있지만 실제로는 비밀번호 단계로 이동한다. (근거[화면+코드]: 그림 11 요약에는 은행·계좌번호·금액 수정 버튼이 없고 하단 버튼은 ‘보내기’다. 코드의 send는 계좌와 은행 검사 후 password 화면을 열며, back-amount만 앞 단계로 돌아가는 경로를 제공한다.)
- **D12** `password` 비밀번호 안내와 숫자 배열 — 어느 계좌의 비밀번호를 입력해야 하는지, 몇 자리인지 글로 알 수 없다. 익숙한 숫자 순서가 아니어서 위치를 짐작해 누르면 잘못 입력할 수 있다. (근거[화면]: 그림 12에는 ‘계좌 비밀번호’와 네 개의 빈 원만 있고 출금계좌나 자리 수 설명은 없다. 숫자가 일반적인 순서가 아닌 위치에 놓여 있고 하단에는 재배열 버튼이 있다.)
- **D13** `password` 입력 완료 동작 — 마지막 숫자를 잘못 눌러도 고칠 시간을 갖기 전에 완료 화면으로 넘어간다. 비밀번호 입력 완료와 송금 실행의 경계가 화면에 드러나지 않는다. (근거[화면+코드]: 그림 12에는 입력을 마친 뒤 누르는 실행 버튼이 없다. 코드의 pw는 네 자리 입력 직후 260밀리초 뒤 done을 표시하며, 별도의 비밀번호 검증 처리도 없다.)
- **D14** `done` 완료 내역과 확인 버튼 — 보냈다는 메시지는 읽을 수 있지만 받는 은행과 계좌번호가 없어 원하는 곳으로 보냈는지 확인하려면 또 다른 버튼을 찾아야 한다. 확인 버튼이 어디로 이동하는지도 알 수 없다. (근거[화면+코드]: 그림 13에는 ‘아래 계좌로’와 금액만 크게 표시되고 은행·계좌번호는 없다. 코드에서 상세보기는 아무 동작도 하지 않으며 finish는 home으로 이동한다.)
- **D15** `err-account` 계좌번호 오류 팝업 — 오류 코드가 가장 먼저 눈에 들어오고 버튼은 단순히 확인이라, 무엇을 고치러 어디로 돌아가는지 판단하기 어렵다. (근거[화면+코드]: 그림 14 팝업 첫 줄은 빨간 ELB00016이고 그 아래에 잘못된 계좌번호와 설명이 나온다. 하단 버튼은 ‘확인’이다. 코드의 close-error는 오류 발생 전 화면으로 돌아가지만 버튼에는 그 목적이 표시되지 않는다.)
- **D16** `err-bank` 은행 오류 문구와 복귀 경로 — 은행을 잘못 골랐는데 과목코드와 계좌번호를 확인하라는 설명이 나와, 맞는 계좌번호를 지우고 다시 입력할 수 있다. 확인 화면으로 돌아가도 은행을 바로 고치는 버튼이 없다. (근거[화면+코드]: 그림 15에는 ETA00325와 ‘해당 계좌번호내 과목코드 오류입니다. 입력하신 계좌번호를 확인해주세요.’가 보인다. 코드의 send는 은행이 정답과 다를 때 이 오류를 띄우고, close-error는 confirm으로 돌아간다. confirm에는 은행 수정 조작이 없다.)
- **D17** `account` 이전 단계 복귀 후 입력값 — 계좌번호를 입력한 뒤 받는 사람 화면을 다시 방문하면 같은 입력을 처음부터 해야 할 수 있다. 은행 수정 후에도 금액을 다시 입력해야 해서 오류 복구 중 앞서 한 작업을 잃는다. (근거[코드]: 코드의 go-account는 계좌번호와 은행을 초기화한다. account-next는 계좌번호가 맞으면 항상 S.amount를 0으로 바꾸므로, 금액 화면에서 계좌 화면으로 돌아갔다가 진행해도 기존 금액을 잃는다.)
- **D18** `home` 홈과 이체 단계의 부가 기능 — 화면에서 사용 가능한 기능처럼 보이는 버튼을 눌러도 아무 변화가 없어 다음 행동을 판단할 수 없다. 특히 이체 중 출금계좌 변경이나 완료 후 상세보기에서도 같은 문제가 생긴다. (근거[화면+코드]: 그림 1~3에는 가입·쿠폰·설정·메뉴 버튼이, 그림 10에는 출금계좌 변경 표시가, 그림 13에는 상세보기·공유·추가이체가 있다. 코드에서 이 기능들의 oos-* 동작은 모두 빈 분기로 처리된다.)

## 과제 밖 입구

과제 경로 위 화면의 다른 메뉴 · 버튼(과제 파일의 `entrances`, 검사 K)이 처음 보이는 자리를 원본과 나란히 적는다. 남아 있는 것과 찾을 수 있는 것은 다르다 (Findlater, McGrenere 2007). 기록만 한다 — 판정 · 고르기에 쓰지 않고, 기준선 · 합격선은 정하지 않았다.
