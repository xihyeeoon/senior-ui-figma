화면설계서 · 이체

실행 20261012-132226 · 최종 생성 (시도 1) · 검사를 통과한 HTML 에서 뽑았다. 색 · 모양은 디자이너의 몫이라 그림은 로우파이 와이어프레임(회색 상자와 글자)이다. 다음 장이 와이어플로, 그다음이 기능-화면 표다.

과제

아래는 은행 앱의 이체 화면을 HTML 한 파일로 만든 것이다 (8화면). 65세 이상 고령 사용자가 이체 과업 — 받는 사람 정하기, 계좌번호와 은행 넣기, 금액 넣기, 확인, 본인 확인, 완료 — 을 혼자서 끝낼 수 있도록 이 화면들을 다시 설계하라.

계획의 변경 목록

#무엇을왜대응 진단
C1홈 첫 화면에 출금계좌 이름과 ‘이 계좌에서 이체하기’를 세로로 배치한다. 이체 버튼은 화면 너비의 주 행동 버튼으로 만들고, 통장 이름은 약 20px의 진한 글씨로 충분히 줄바꿈한다. 가입과 쿠폰 등은 ‘다른 서비스 보기’ 아래로 이동한다.출금계좌와 이체 시작 행동을 함께 읽고 광고성 행동과 구분하게 한다.D1 이체를 시작하려는 사용자가 작은 이체 버튼보다 넓은 앱카드 가입이나 쿠폰 버튼을 먼저 누를 수 있다. 출금할 통장 이름도 작고 여러 줄로 끊겨 어떤 계좌의 이체인지 읽기 어렵다.
C2홈의 메시지·지갑·알림·전체메뉴는 그림 대신 읽을 수 있는 이름을 붙인 버튼으로 제공한다. 하단의 홈·금융·상품·혜택·주식도 진한 글씨와 충분한 누름 영역을 갖게 한다. 쉬운홈·홈화면 설정·금액 숨기기는 홈 상단의 ‘홈 설정’에서 접근하게 한다. 본문은 약 20px, 제목은 약 26px, 조작 영역은 최소 높이 56px를 목표로 하며 글자 확대 시 내용과 버튼이 겹치지 않도록 스크롤을 허용한다.기능 이름을 직접 읽을 수 있게 하고 화면 끝에 숨은 설정을 찾는 부담을 줄인다.D2 상단 아이콘은 모양만으로 기능을 알아볼 수 없고, 하단 메뉴 이름은 작고 흐려 읽기 어렵다. 쉬운홈을 찾으려 해도 화면 끝까지 내려야 한다.
C3받는 사람 화면의 첫 행동을 ‘새 계좌로 보내기’라는 큰 버튼으로 바꾼다. 그 아래 자주쓰는 계좌·내 계좌·최근 계좌를 두고 비어 있으면 ‘등록된 계좌가 없습니다. 새 계좌로 보내기를 눌러 주세요’라고 표시한다. 검색·받는 사람 관리·자주쓰는 계좌 편집·다건이체는 각각 이름 있는 버튼으로 유지한다.등록된 사람이 없어도 새 계좌 입력으로 이어지는 경로가 분명해진다.D3 직접 입력이 버튼인지 입력창인지 구분하기 어렵다. 목록이 모두 0개여서 고를 사람이 없는 사용자는 무엇을 해야 할지 멈출 수 있다.
D4 검색과 관리의 구분이 그림만으로 어렵다. 눌러도 반응 없는 메뉴에서는 사용자가 자신의 터치가 실패했다고 생각해 반복해서 누르거나 과업을 중단할 수 있다.
C4계좌 화면 제목을 ‘받는 계좌를 입력해 주세요’로 바꾸고 ‘계좌번호는 하이픈 없이 숫자만 입력하세요’를 상시 표시한다. 계좌번호와 은행에 각각 명확한 이름을 붙인다. ‘계좌 확인하고 금액 입력’ 버튼 아래에는 부족한 값에 따라 ‘계좌번호를 입력해 주세요’ 또는 ‘은행을 선택해 주세요’를 표시하고, 준비되지 않은 버튼은 실제 비활성 상태로 둔다.입력 방식과 진행 조건을 버튼 색만 보고 추측하지 않게 한다.D5 ‘없이 숫자만 입력’에서 무엇을 빼라는 것인지 알기 어렵다. 다음 버튼이 흐리지만 계좌번호와 은행 중 무엇이 부족한지는 설명하지 않아 진행 방법을 찾기 어렵다.
C5계좌 화면 진입 시 window.PRESERVED.ACC_KEYS를 읽어 모든 숫자 버튼을 DOM에 그리고 키패드를 바로 보여 준다. 숫자 버튼에는 경계와 간격을 둔다. ‘한 자리 지우기’와 ‘전체 지우기’를 서로 떨어뜨려 이름으로 표시하고 전체 삭제에는 확인을 요구한다. 최대 자리 수 안내는 입력칸 가까이에 두며 추가 숫자를 받지 못했을 때 이유를 새로 표시한다.키패드를 여는 숨은 조작과 기호 해석을 없애고 실수로 전체 번호를 지우는 일을 줄인다.D6 처음에는 숫자 키패드가 없어 입력을 시작하려면 어디를 눌러야 하는지 알아내야 한다. 키패드가 열린 뒤에는 숫자 사이의 버튼 경계가 없고 삭제가 기호뿐이라 잘못 누르거나 수정 방법을 못 찾을 수 있다.
D5 ‘없이 숫자만 입력’에서 무엇을 빼라는 것인지 알기 어렵다. 다음 버튼이 흐리지만 계좌번호와 은행 중 무엇이 부족한지는 설명하지 않아 진행 방법을 찾기 어렵다.
C6은행 선택을 전체 화면으로 바꾸고 기관 이름 중심의 한 열 목록을 사용한다. window.PRESERVED.BANKS와 window.PRESERVED.SECS를 읽어 두 목록의 모든 항목을 화면을 열 때 DOM에 만든다. ‘은행 목록’과 ‘증권사 목록’은 진한 글씨의 전환 버튼으로 제공한다. 검색어가 비었을 때 전체 항목을 유지하며, 검색 결과가 없어도 목록 전환과 검색 지우기를 사용할 수 있게 한다. reveal: 계좌 화면의 ‘은행 선택’을 누르면 목록이 열리고, 숨겨진 증권사 목록은 ‘증권사 목록’, 숨겨진 은행 목록은 ‘은행 목록’을 눌러 표시한다. 검색으로 숨겨진 항목은 ‘검색 지우기’를 누르고 해당 목록으로 전환한 뒤 스크롤하면 실제로 누를 수 있다. 목록 내부에는 추가 접힘 묶음을 만들지 않는다.작은 그림 대신 기관 이름을 크게 비교하고 모든 선택지에 명확한 접근 경로를 제공한다.D7 작은 기관 이름을 세 열에서 비교하며 여러 번 내려야 해서 비슷한 이름을 잘못 고를 수 있다. 흐린 증권사 탭을 선택할 수 없는 글자로 오해할 수도 있다.
C7금액 화면 상단에는 ‘받는 계좌’와 선택한 은행·계좌번호를 진하게 표시한다. 출금계좌는 별도의 ‘보내는 계좌’ 영역에 두고 ‘출금계좌 변경’ 버튼을 붙인다. 중앙에는 항상 진한 ‘보낼 금액’ 제목, 숫자 금액, 한글 금액 읽기를 함께 표시한다. 출금가능금액도 진한 본문 글씨로 표시한다.돈의 출발점과 도착점을 구분하고 입력한 금액의 자릿수를 확인하게 한다.D8 핵심 질문과 출금가능금액이 흐려 읽기 어렵다. 보내는 계좌와 받는 계좌가 위쪽에 작은 글씨로 모여 있고 받는 계좌를 ‘아래 계좌’라고 불러, 어느 계좌로 보내는지 다시 확인하기 어렵다.
C8window.PRESERVED.AMT_KEYS를 읽어 모든 금액 숫자 버튼을, window.PRESERVED.QUICK을 읽어 모든 빠른 금액 버튼을 금액 화면 DOM에 처음부터 보이게 만든다. 빠른 금액의 누적 동작은 유지하되 각 버튼에 ‘더하기’ 또는 ‘출금가능금액 전체’를 명시하고 변경된 총액을 즉시 표시한다. 잔액 초과 숫자 입력이나 빠른 금액 조작은 임의로 잔액에 맞추지 않고 직전 금액을 유지하면서 ‘출금가능금액을 넘었습니다. 금액을 줄여 주세요’를 새로 표시한다. 전체 금액 선택 시 총액을 다시 읽을 수 있게 안내한다. ‘한 자리 지우기’와 ‘금액 다시 입력’을 제공한다.누적과 전체 금액 선택의 결과를 읽게 하고, 입력을 무시하거나 다른 금액으로 바꾸는 이유 없는 동작을 없앤다.D9 빠른 금액 버튼을 다시 누르면 금액이 누적되므로 원하는 금액보다 크게 입력할 수 있다. 잔액을 넘기는 숫자를 눌렀는데 화면이 그대로이거나 빠른 금액이 잔액으로 바뀌면 터치 실패로 오해하거나 의도하지 않은 금액을 확인할 수 있다.
D6 처음에는 숫자 키패드가 없어 입력을 시작하려면 어디를 눌러야 하는지 알아내야 한다. 키패드가 열린 뒤에는 숫자 사이의 버튼 경계가 없고 삭제가 기호뿐이라 잘못 누르거나 수정 방법을 못 찾을 수 있다.
C9확인 화면은 ‘받는 계좌’, ‘보낼 금액’, ‘보내는 계좌’, ‘수수료’ 순서의 큰 정보 블록으로 구성한다. 받는 계좌에는 은행과 전체 계좌번호를 표시한다. 원본의 고정 메모를 실제 수취인 이름으로 사용하지 않는다. 실제 계좌 명의 확인 결과가 없는 구현에서는 이를 분명히 알리고 은행·계좌번호를 확인하도록 안내한다. 받는분 메모와 내통장 메모는 ‘선택 사항: 메모’ 아래 유지하고 계좌 명의와 무관한 메모라는 설명을 붙인다. reveal: ‘메모 펼치기’를 누르면 두 메모와 각각의 편집 버튼이 나타난다.고정 메모를 검증된 받는 사람 이름으로 오해하지 않고 핵심 송금 정보를 먼저 확인하게 한다.D10 실제 받는 사람 이름을 확인했다고 착각할 수 있다. 계좌정보는 작은 요약 행에 있고 김철수라는 이름은 메모에만 표시되어, 메모를 계좌 명의자로 잘못 읽을 가능성이 있다.

D15err-account계좌번호 오류 팝업오류 코드가 가장 먼저 눈에 들어오고 버튼은 단순히 확인이라, 무엇을 고치러 어디로 돌아가는지 판단하기 어렵다.

D17account이전 단계 복귀 후 입력값계좌번호를 입력한 뒤 받는 사람 화면을 다시 방문하면 같은 입력을 처음부터 해야 할 수 있다. 은행 수정 후에도 금액을 다시 입력해야 해서 오류 복구 중 앞서 한 작업을 잃는다.
