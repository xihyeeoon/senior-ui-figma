# 디자이너용 변경 설명서

최종: 생성 (시도 2)

실행 `20261013-170616` · 시도 2 에서 검사를 통과한 빌드 · 커밋 `385eced92999`.

이 파일은 구조 시안의 설명이다. 색·글꼴·간격 같은 시각 디테일은 평가하지 않았다. 화면 구성과 흐름, 그리고 바꾼 이유를 옮겨 적는다.

## 화면 대응

| 원본 | 재설계 |
|---|---|
| home | home |
| recipient | recipient |
| bank | bank |
| account | account |
| amount | amount |
| confirm | confirm |
| password | password |
| done | done |
| err-account | (없어짐) |
| err-bank | (없어짐) |

재설계 화면의 순서와 하는 일:

1. `home` — 출금할 계좌를 확인하고 이체를 시작한다.
2. `recipient` — 받는 사람을 정하는 방법을 선택한다. 직접 입력 또는 원본의 계좌 목록 기능을 이용한다.
3. `account` — 받는 계좌번호를 입력하고 은행 선택을 연다. 선택한 은행과 계좌번호를 확인한 뒤 다음으로 진행한다.
4. `bank` — 받는 은행 또는 증권사를 선택하고 계좌 입력 화면으로 돌아간다.
5. `amount` — 출금계좌와 받는 계좌를 확인하고 보낼 금액을 입력한다.
6. `confirm` — 받는 은행·계좌번호·금액·수수료와 메모를 확인하고 보내기를 선택한다.
7. `password` — 출금계좌 비밀번호 네 자리로 본인 확인을 한다.
8. `done` — 이체 완료 내역을 확인하고 홈으로 돌아가거나 원본의 후속 기능을 선택한다.

- **D16** `done` 완료 내역과 확인 버튼 — 성공 표시를 보더라도 어느 은행의 어느 계좌로 보냈는지 바로 확인할 수 없다. 확인이 완료 화면을 닫는 것인지 또 이체를 승인하는 것인지 혼동할 수 있다. (근거[화면]: 그림 18에는 체크 표시와 '아래 계좌로 10,000원 보냈어요.'가 있지만 은행과 계좌번호는 보이지 않는다. 하단 주 버튼은 '확인'이고, 상세보기는 따로 있다.)
- **D17** `err-account` 계좌번호 오류 팝업 — 낯선 오류 코드가 먼저 보여 무엇을 고쳐야 하는지 파악이 늦어진다. 확인 버튼은 오류를 닫는다는 뜻만 보여 다음 행동이 계좌번호 수정임을 예측하기 어렵다. (근거[화면+코드]: 그림 19 팝업 맨 위에는 빨간 ELB00016이 있고, 그 아래 여러 줄에 걸쳐 입력 계좌번호와 오류 설명이 표시된다. 버튼 문구는 확인이다. 코드 close-error는 저장된 오류 발생 화면으로 돌아간다.)
- **D18** `err-bank` 은행 오류 설명과 복귀 — 틀린 것은 은행인데 계좌번호를 고치라고 안내하여 맞는 번호를 지울 수 있다. 확인 화면으로 돌아가도 은행을 고치는 조작이 없어 어디로 가야 하는지 막힌다. (근거[코드]: err-bank 마크업은 ETA00325와 '해당 계좌번호내 과목코드 오류입니다. 입력하신 계좌번호를 확인해주세요.'를 표시한다. send 분기는 계좌번호가 맞고 은행이 정답과 다를 때 이 오류를 띄우며 errFrom을 confirm으로 설정한다. close-error는 confirm으로 복귀한다. 이 오류의 캡처는 제공되지 않았다.)

재시도에서의 반성 (계획이 바뀐 경우 그 이유):

- 시도 2: 계좌번호가 비어 있을 때 모두 지우기 버튼이 확인창을 열지 않아, 오류 경로의 다음 조작인 dialog-yes 버튼에 접근할 수 없었다. (계획 변경 0건)

## 과제 밖 입구
