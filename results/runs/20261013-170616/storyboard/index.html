실행 20261013-170616 · 최종 생성 (시도 2) · 검사를 통과한 HTML 에서 뽑았다. 색 · 모양은 디자이너의 몫이라 그림은 로우파이 와이어프레임(회색 상자와 글자)이다. 다음 장이 와이어플로, 그다음이 기능-화면 표다.

과제

아래는 은행 앱의 이체 화면을 HTML 한 파일로 만든 것이다 (8화면). 65세 이상 고령 사용자가 이체 과업 — 받는 사람 정하기, 계좌번호와 은행 넣기, 금액 넣기, 확인, 본인 확인, 완료 — 을 혼자서 끝낼 수 있도록 이 화면들을 다시 설계하라.

계획의 변경 목록

#무엇을왜대응 진단
C1홈 첫 영역을 출금계좌 카드로 구성한다. 로고 자리, 계좌 이름, 금액 숨김 상태를 유지하고 긴 계좌 설명은 줄을 나눠 읽게 한다. 카드 아래에 너비가 넓은 '이체하기' 버튼을 둔다. IRP 안내와 카드 가입·쿠폰·포인트·소비·추천서비스·금융그룹·자산 연결 이벤트는 그 아래에 관련 기능별 카드로 재배치하며 제거하지 않는다.첫 화면에서 이체 시작점을 찾고 광고성 기능과 구별하게 한다.D1 이체를 시작하려는 사용자가 작은 이체 버튼을 찾기 전에 카드 가입이나 쿠폰 받기를 먼저 누를 수 있다. 계좌 설명도 여러 줄로 나뉘어 어느 계좌에서 보내는지 읽기 어렵다.
C2홈 상단 메시지·지갑·알림·전체메뉴는 원본 아이콘 자리와 이름을 함께 둔 두 열 바로가기로 만든다. 하단 다섯 탭도 아이콘과 진한 이름을 함께 유지한다. 쉬운홈·홈화면 설정·금액 숨기기는 출금계좌 카드 다음의 홈 설정 묶음으로 올린다. 모든 홈 기능은 접지 않고 스크롤로 접근하게 하며 원본의 연결을 유지한다.아이콘 뜻을 추측하거나 화면 끝까지 내려 설정을 찾지 않게 한다.D2 상단 아이콘의 뜻을 구별하기 어렵고 하단 탭 이름은 작고 흐려 읽기 어렵다. 쉬운홈이나 홈화면 설정을 찾으려면 긴 화면 끝까지 내려가야 한다.
C3받는 사람 화면의 첫 선택을 테두리와 배경이 분명한 큰 '계좌번호 직접 입력' 버튼으로 만든다. '받는 분의 은행과 계좌번호를 준비해 주세요'를 바로 아래에 둔다. 카메라 그림 자리는 같은 버튼 안에 '계좌번호 입력' 설명과 함께 유지하며 원본처럼 직접 입력 화면으로 연결한다.계좌번호를 가진 사용자가 시작할 조작을 명확히 알게 한다.D3 계좌번호를 알고 있어도 직접 입력이 누르는 곳인지 알아채지 못할 수 있다. 오른쪽 카메라를 눌러야 입력할 수 있다고 오해할 수도 있다.
C4자주쓰는 계좌·내 계좌·최근을 별도 카드로 묶고 각 카드에 '등록된 계좌가 없습니다'를 표시한다. 원본의 목록 진입과 편집 조작은 이름이 있는 버튼으로 유지한다. 검색·받는 사람 관리·다건이체는 아이콘과 이름을 함께 둔 보조 기능 영역에 배치하고 접지 않는다.빈 목록을 반복해서 누르지 않게 하고 보조 기능도 이름으로 찾게 한다.D4 세 목록이 모두 비어 있지만 다음에 무엇을 해야 하는지 안내가 없어 목록을 반복해서 펼칠 수 있다. 검색과 받는 사람 관리도 그림만으로 뜻을 알아야 한다.
C5계좌 화면 제목을 '받는 계좌를 입력해 주세요'로 바꾼다. 계좌번호에는 '하이픈 없이 숫자만 입력'이라는 완전한 안내를 둔다. 은행과 계좌번호를 하나의 받는 계좌 카드 안에 묶고 필수 항목임을 글로 표시한다. 다음 버튼 위에 현재 빠진 항목을 안내한다. 계좌번호와 은행이 모두 있을 때만 다음을 실제로 활성화한다.회색 버튼의 이유와 남은 입력을 알게 한다.D5 입력 안내의 문장이 불완전하고, 다음이 왜 회색인지 알기 어렵다. 계좌번호만 넣고 은행 선택을 빠뜨린 채 다음을 반복해서 누를 수 있다.
C6계좌 화면 진입 시 숫자판을 바로 표시한다. window.PRESERVED.ACC_KEYS를 참조해 모든 숫자 키를 DOM에 렌더링하고 원본의 익숙한 숫자판 순서를 유지한다. 각 키에 구획과 충분한 간격을 둔다. 숫자판의 삭제에는 '한 자리 지우기', 입력란의 전체 삭제에는 '모두 지우기'라는 이름을 붙인다. 전체 삭제는 실행 전 같은 화면에서 확인받는다. 입력 번호는 큰 글씨로 전체를 볼 수 있게 줄바꿈하고 자릿수도 표시한다.숫자판을 여는 조작을 찾지 않게 하고 한 자리 삭제와 전체 삭제를 구별하게 한다.D6 입력란을 눌러야 숫자판이 나온다는 사실을 놓칠 수 있다. 키 사이에 구획이 없어 옆 숫자를 잘못 누르거나 화살표를 이전 화면으로 가는 버튼으로 오해할 수 있다.
C7진행 중 입력한 은행·계좌번호·금액을 화면 이동과 오류 복귀에서 보존한다. recipient에서 직접 입력을 다시 선택해도 초기화하지 않는다. 뒤로 버튼에는 돌아갈 곳을 글로 표시하고 X는 '이체 취소'로 표시한다. 취소 시 같은 화면에서 입력 내용을 버릴지 확인한다. 새 이체를 명시적으로 시작할 때만 새 입력 상태를 만든다.탐색이나 수정 때문에 긴 번호와 금액을 다시 입력하지 않게 한다.D7 받는 사람 화면으로 돌아가 직접 입력을 다시 선택하면 이미 입력한 계좌번호와 은행이 사라져 긴 번호를 처음부터 다시 넣어야 한다.
D12 숫자를 눌렀는데 금액이 바뀌지 않거나 빠른 금액이 예상과 다르게 적용되어 입력 실패로 생각할 수 있다. 계좌를 고치러 갔다 오면 입력 금액도 잃는다.
C8은행 선택 화면은 두 열 카드 격자로 만든다. 각 카드에 원본 로고 자리를 유지하고 기관 이름은 줄바꿈해 끝까지 표시한다. window.PRESERVED.BANKS와 window.PRESERVED.SECS를 참조하여 두 목록의 모든 항목을 화면 진입 시 DOM에 렌더링한다. 기관 이름을 생략하거나 값을 다시 작성하지 않는다.로고뿐 아니라 전체 이름으로 기관을 구별하게 한다.D8 긴 기관 이름이 잘리면 비슷한 기관을 구별하기 어렵다. 로고만 보고 고르면 같은 계열의 은행과 증권사를 혼동할 수 있다.
C9은행·증권사 탭에 분명한 선택 표시와 큰 이름을 두고 목록 위에 검색창을 둔다. 빈 검색어에서는 선택 탭의 전체 목록을 보여 준다. 다른 탭의 목록도 DOM에 유지한다. 검색 중 탭을 바꾸면 검색어를 비워 해당 전체 목록을 보이며, '검색 지우기'도 제공한다. 아래 목록은 끝까지 스크롤할 수 있게 한다. 닫기 버튼은 '선택 취소 · 계좌 입력으로'로 표시한다. 선택 즉시 원본처럼 account로 돌아가 선택한 기관을 큰 이름과 로고 자리로 보여 준다.기관을 검색하거나 전체 목록에서 찾을 수 있고 다른 탭도 놓치지 않게 한다.D9 찾는 기관이 아래에 있는지 다른 탭에 있는지 알기 어렵다. 목록을 오래 훑다가 닫기 표시를 눌러 선택 없이 돌아갈 수 있다.
C10금액 화면 맨 위에 '받는 계좌' 카드로 은행과 전체 계좌번호를 크게 표시한다. '보내는 계좌'는 별도 카드로 구분하고 원본의 출금계좌 변경 조작과 그림 자리를 유지한다. 가운데 금액 입력에는 항상 '보낼 금액'이라는 이름을 두고 숫자 금액과 읽기용 한글 금액을 함께 표시한다.송금 방향과 자릿수를 확인한 뒤 금액을 넣게 한다.D10 긴 출금계좌 이름과 '아래 계좌로'라는 표현 때문에 보내는 곳과 받는 곳을 구별하기 어렵다. 받는 은행과 번호는 작고 흐려 확인하지 못한 채 금액을 넣을 수 있다.
D11 전액을 금액 증가 버튼과 같은 방식으로 누르거나 00과 0을 혼동해 예상보다 큰 금액을 만들 수 있다. 표시된 숫자만으로는 자릿수를 다시 세어야 한다.
C11window.PRESERVED.AMT_KEYS를 참조해 모든 금액 키를 구획 있는 숫자판으로 렌더링한다. window.PRESERVED.QUICK을 참조해 모든 빠른 금액 선택지를 DOM에 렌더링한다. 증가 동작에는 '현재 금액에 더하기', 전액 동작에는 '출금 가능한 금액 전체'라는 설명을 붙여 구별한다. 두 자리 입력 키에는 두 자리가 추가됨을 보조 글로 알린다. 삭제 버튼은 '한 자리 지우기'로 표시한다. 모든 금액 선택지는 처음부터 표시하고 접지 않는다.금액 증가·전액 설정·숫자 추가의 차이를 이해하고 누르게 한다.D11 전액을 금액 증가 버튼과 같은 방식으로 누르거나 00과 0을 혼동해 예상보다 큰 금액을 만들 수 있다. 표시된 숫자만으로는 자릿수를 다시 세어야 한다.
C12출금 가능 금액을 진한 글씨로 표시한다. 숫자 입력이나 빠른 금액 증가가 출금 가능 금액을 넘으면 기존 금액을 유지하면서 '출금 가능한 금액을 넘었습니다. 금액을 줄여 주세요'를 입력부 아래에 새로 표시한다. 초과 금액을 말없이 무시하거나 잔액으로 바꾸지 않는다. 금액이 없으면 다음 위에 금액 입력 안내를 둔다.입력이 반영되지 않은 이유를 알고 같은 화면에서 고치게 한다.D12 숫자를 눌렀는데 금액이 바뀌지 않거나 빠른 금액이 예상과 다르게 적용되어 입력 실패로 생각할 수 있다. 계좌를 고치러 갔다 오면 입력 금액도 잃는다.
