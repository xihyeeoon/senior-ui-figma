# prompts/principles/ — 생성 프롬프트에 넣는 문헌 원칙

재구성 실행에 `--principles ga` 또는 `--principles na` 를 주면 이 폴더의 같은 이름 파일이
진단·계획 · 생성 · 다듬기 프롬프트에 들어간다 (`senior_ui/restructure/principles.py`, 글의 자리는
`docs/restructure-prompt.md` 의 "원칙" 절). 기본은 `none` — 아무 파일도 읽지 않고 프롬프트는
원칙 옵션이 생기기 전과 바이트까지 같다.

`kb/` 에 두지 않는 이유: `kb/README.md` 가 그 폴더의 규칙 모음은 "생성에는 쓰지 않는다" (사후
대조 전용) 고 정해 두었다. 이 폴더의 원칙은 생성에 쓰는 것이라 따로 둔다.

## 조건

| 조건 | 파일 | 무엇 |
|---|---|---|
| `none` | (없음) | 원칙 없음 — 모델 자체 판단. 실행 ④ `20261013-170616` 이 이 조건이다 |
| `ga` | `ga.json` | 고정 원칙 9개 (S02 · S03 · S04 · S06 · S08 · S09 · S17 · S22 · C01). 모든 화면에 적용하라고 준다 |
| `na` | `na.json` | 화면 수준 원칙 26개 + C01 (27개, S07 없음). 모델이 화면마다 고른다 |

S07 은 없다 — 흐름을 바꾸는 문장이라 흐름 고정 단계 (`--mode layout`) 에서 뺐다. `ga` 의 아홉
항목은 `na` 의 같은 id 항목과 글자까지 같다 (`tests/test_principles.py` 가 본다).

## 파일 모양

```json
{"condition": "ga" | "na",
 "source_db": "guideline-db-1014 (…)",
 "items": [{"id", "given_text", "db_text", "change", "source", "strength"}]}
```

| 칸 | 뜻 | 프롬프트에 들어가나 |
|---|---|---|
| `id` | 원칙 번호 (S01… · C01). 계획의 `applied[].id` 가 이것을 가리킨다 | 들어간다 (`- <id>: <given_text>`) |
| `given_text` | 모델에게 주는 문장 | 들어간다 — 한 글자도 바꾸지 않고 그대로 |
| `db_text` | 지침 DB 의 원래 문장. 바꾸지 않은 항목은 `given_text` 와 같다 | 넣지 않는다 |
| `change` | DB 문장을 어떻게 바꿨나 — `그대로` · `예시만: …` · `바꿈: …` | 넣지 않는다 |
| `source` | 출처 (아래 G · N · M 의 지침 번호, 또는 쪽수) | 넣지 않는다 |
| `strength` | 출처 수 — 1 · 2 · 3, 또는 `"보조"` (지침 DB 가 보조로 둔 것) | 넣지 않는다 |

**strength 는 프롬프트에 넣지 않는다.** 원칙의 강약을 모델에게 알리면 조건 사이의 차이가
"원칙이 무엇인가" 가 아니라 "몇 편이 말했나" 로 섞인다. 분석할 때 쓰는 값이다.

**바꾼 문장은 `change` 칸에 있다.** 일부 DB 문장은 연구 원칙과 부딪혀 바꿔서 준다.

- 기능 보존 — "할 수 있는 일은 줄이지 않는다" (검사 K 과제 밖 입구 · I 선택지 · L 그림 자리 ·
  J 오류 경로). DB 의 "빼라 · 드러내지 않는다" 는 "접거나 덜 눈에 띄는 자리로 옮긴다 · 지우지
  않는다" 로 (S01 · S02 · S04).
- 흐름 고정 — `--mode layout` 은 화면과 그 차례를 원본 그대로 둔다 (검사 M). "거치는 화면 수를
  줄인다" 는 뺐다 (S06), 흐름을 바꾸는 S07 은 통째로 뺐다.
- 과제에 묶인 예 — DB 는 이체 과제로 쓰여 있다 (`home` · `confirm` · 계좌번호). 공과금에도 쓰도록
  예만 일반 문장으로 바꿨다 (`예시만: …`).

`바꿈` 은 뜻이 달라진 것, `예시만` 은 예 · 낱말만 다듬어 뜻이 같은 것, `그대로` 는 DB 문장 그대로다.

## 출처

고령자 UI 리뷰 논문 셋이다.

| 기호 | 논문 |
|---|---|
| G | Gomez-Hernandez 외 (2023), *JMIR mHealth and uHealth* |
| N | Nurgalieva 외 (2019), *IEEE Access* |
| M | Mattick 외 (2024), *OzCHI* |

`source` 의 `G01` · `N07` · `M04` 같은 번호는 그 논문의 지침 번호다 (지침 DB `guideline-db-1014`,
조율 채팅의 프로젝트 문서 — 세 리뷰에서 뽑아 원문과 대조한 것). C01 은 Mattick 본문 p.150–151 에서
뽑았다.

## 고칠 때

- 원칙 문장을 바꾸면 그 조건으로 만든 실행과 같은 조건이 아니다. summary 의 `principles.sha256`
  (이 파일의 sha256, 줄끝 LF 로 맞춤) 이 실행마다 남으니, 고친 뒤의 실행은 그 값으로 가른다.
- `given_text` 를 바꾸면 `db_text` · `change` 도 함께 맞춘다.
